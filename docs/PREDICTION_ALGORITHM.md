# PREDICTION_ALGORITHM.md — 燃烧速率与耗尽预测算法

> v0.2 引入 · 实现于 [src-tauri/src/predict.rs](../src-tauri/src/predict.rs)（纯函数、零 IO、7 个单元测试全覆盖）
> 设计原则：**区间 + 置信度，绝不输出伪精确点估计**——社区经验表明启发式用量预测普遍偏乐观约 35%，与其给一个看似精确的错误答案，不如给一个诚实的不确定区间。

## 1. 目标

回答用户真正关心的问题：「**照这个用法，我的额度几点用完？**」——并且在不该回答的时候（数据不足、不在燃烧、重置先到）如实沉默。

## 2. 数据来源

- 每个限额维度（quota bucket）的**剩余百分比序列**：来自本地 SQLite `snapshots` 表的历史快照（调度器每 30 秒 tick 一次，抓取成功即落库），取近 24 小时窗口。
- 采样间隔**天然不均匀**：刷新策略含指数退避与 ±10% 抖动，还有活动加速（Idle→Active 边沿补刷），所以样本点不是等间隔的——算法必须显式处理这一点。
- DeepSeek 余额趋势另用 `balance_samples` 表的原始 (时间戳， 余额) 序列（近 14 天）。

## 3. 方法：新近加权最小二乘

ccusage 等工具的速率计算是**端点法**（首末时间戳 + 总量 ÷ 时长）——实现简单，但对端点处的单个异常样本极其敏感。本引擎对窗口内样本做加权一元回归：

- 自变量 `x` = 距窗口首样本的小时数，因变量 `y` = 剩余百分比；
- 权重 `w = 0.5 + x / span` ∈ **[0.5, 1.5]**——越新的样本权重越大；
- 斜率即燃烧速率（%/小时，负值表示在消耗）。

**为什么加权**：用户中途停下工作时，近期的平坦样本应当压低预测速率——普通 OLS 会被早期的陡降拉偏（单元测试 `新近加权_近期减速时预测贴近近期速率` 专门验证此性质）。整窗百分比样本的量化噪声（部分 Provider 只给整数百分比）也会被回归平滑掉。

耗尽时间 = `最新剩余 ÷ |斜率|`，输出为绝对时间戳。

## 4. 重置截断

剩余额度在两次重置之间**只降不升**——序列中「新样本比紧邻前一个样本高出 30 点以上」只可能来自重置填充。从最新样本往回扫，遇到跳升即截断其前的全部历史，回归只用当前窗口的样本。

> v0.2 单测抓出的初版 bug：曾按"高于其后最小值 +5"判定，会把**单调下降的正常序列**误判为跳升；也曾把截断方向写反，保留了重置**前**的旧窗口。两个 bug 都被测试在集成前拦下。

## 5. 四道防误报门槛

以下任一情况**不输出预测**（宁可不显示，不瞎猜）：

| 门槛 | 理由 |
|---|---|
| 斜率 ≥ -0.1%/h | 未在有效燃烧（空闲/回升）——"预计 999 小时后耗尽"没有行动价值 |
| 耗尽点超出 7 天 | 太远，预测会被后续行为推翻 |
| **重置先于耗尽到达** | 额度会先回填，耗尽预测无意义——最容易被忽略的坑 |
| 样本 < 3 个或窗口 < 10 分钟 | 数据不足以支撑任何方向性结论 |

## 6. 区间与置信度

- **区间**：耗尽时间 ±25%（下限 10 分钟、上限 6 小时）——量化噪声与行为突变无法消除，用区间诚实地表达。
- **置信度三级**：
  - **高**：≥8 个样本、跨度 ≥45 分钟、加权 R² ≥ 0.85；
  - **中**：≥4 个样本、跨度 ≥20 分钟；
  - **低**：≥3 个样本、跨度 ≥10 分钟。

## 7. 切换建议

当某 Provider 的**代表桶**（与浮窗同一套优先级语义：聚合桶 > 5h > 月度 > 周 > 其他，reserve 永远垫底）剩余量低于用户设置的提醒阈值时，按剩余量降序列出**其他已连接 Provider** 的代表余量（前 3 名）。判定完全在 Rust 侧完成，前端只渲染。

## 8. DeepSeek 余额趋势

对近 14 天的余额原始序列做同样的加权回归：斜率（¥/小时）× 24 = 日均消耗，可支撑天数 = 当前余额 ÷ 日均消耗。仅当余额在净减少（斜率 < 0）且日均消耗 > ¥0.01 时输出。**只估趋势，不做差值冒充消费**（DATA_MODEL 红线）。

## 9. 通知

- 预测耗尽 ≤ 60 分钟 → Windows 系统通知「按当前速度约 X 后耗尽」；同一桶只提醒一次（kv 去重），回升超过 120 分钟自动复位，下次跌破可再次提醒。
- 常规阈值通知（warn/crit）见 [REFRESH_STRATEGY](REFRESH_STRATEGY.md) 与设置页。

## 10. 已知局限

- **整数百分比量化**：部分 Provider 只回报整数百分比，短窗口内斜率噪声较大——置信度分级会如实反映。
- **燃烧假设是线性的**：真实用量是突发的（一波高强度编码后长时间空闲）。新近加权缓解但不根治；窗口内的行为突变依赖新样本快速覆盖。
- **会话型 Provider 的历史盲区**：MiMo/WorkBuddy 数据只能经登录窗读取，后台每 30 分钟验证一次——两次验证之间的燃烧对预测不可见。
- **多账号**：预测按 (Provider, bucket) 粒度，多账号支持落地后需扩展到账号粒度。
